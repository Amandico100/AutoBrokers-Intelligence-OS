## 1. O que foi corrigido (ponto central do batch)
O 43P1 satisfazia a FK do `tenant_connections` reusando o template `whatsapp_zapi` — dívida técnica. O 43P1.1 canoniza:
- **Connector template próprio `portal_browser`** (`ensurePortalBrowserConnectorTemplate`): procura o slug; se faltar, **cria** (category `browser_automation`, connector_kind `portal_browser`, `real_browser_enabled` implícito false, risk high, approval default true); se não puder criar, usa fallback `whatsapp_zapi` **explícito** (warning `portal_browser_template_missing` + flag em metadata) — **nunca silencioso**.
- **Migração**: ao acessar a connection do 43P1, se ela aponta para outro template e o `portal_browser` canônico existe, re-aponta o `connector_template_id` (best-effort, **preservando os dados**).

## 2. Como Portal Browser deixa de depender de whatsapp_zapi
`PORTAL_BROWSER_CONNECTOR_SLUG = 'portal_browser'` é a fonte canônica. A criação da connection usa `ensurePortalBrowserConnectorTemplate`. O `whatsapp_zapi` só aparece como fallback de FK **com warning explícito** registrado em `tenant_connections.metadata` (`connector_slug`, `template_fallback`, `warning`) e no log — auditável, não silencioso.

## 3. Global Portal Catalog
`GLOBAL_PORTAL_DEFINITIONS` (catálogo global canônico, **vazio** até o intake real — nunca inventar URL) + `getGlobalPortalCatalog()`. `PortalDefinitionRecord` ganhou `scope: 'global' | 'tenant_draft' | 'tenant_override'`. Definições criadas pelo admin nascem `tenant_draft`.

## 4. Resolve canônico
`resolvePortalCanonical(globalDefs, tenantDefs, accounts, ctx)`: **tenant override/draft tem prioridade** sobre o global; retorna `portal_source` (`global|tenant_override|tenant_draft|none`), `account_source` (`tenant`) e `connector_template: 'portal_browser'`, sempre `real_action_allowed=false`. A rota `/resolve` agora combina `getGlobalPortalCatalog()` + definições do tenant. O `resolvePortalForJourney` antigo foi mantido (compat) e o canônico é o novo padrão.

## 5. Como as contas continuam tenant-private
`PortalAccountRecord`, `CredentialRefRecord` e `SessionRefRecord` permanecem em `tenant_connections.connection_config.portal_accounts[]` do tenant — privados por company. Catálogo global **nunca** contém credencial/sessão.

## 6. Como os dados do 43P1 foram preservados
A connection do 43P1 já usava o nome determinístico `autobrokers_portal_browser` e os arrays `portal_definitions[]`/`portal_accounts[]` — **mesmas chaves**. O 43P1.1 não recria nem duplica: só re-aponta o `connector_template_id` para o `portal_browser` (migração in-place) e segue lendo os mesmos arrays. Zero perda.
