## 2. Endpoint criado (não havia equivalente)
`GET /api/attendance/connectors/infocap/diagnostics` — auth Iron Session + `users_v2.company_id` (mesmo padrão das rotas de atendimento). Não existia endpoint de diagnóstico por conector no Vault que retornasse este shape específico, então criei um dedicado e mínimo (sem duplicar as rotas genéricas de `/api/vault/connections`).

## 3. Resposta
```json
{
  "ok": true,
  "provider": "infocap",
  "template_found": true,
  "tenant_connection_found": true,
  "status": "connected|draft|error|null",
  "base_url_configured": true,
  "secret_ref_present": true,
  "ready_for_real_lookup": true,
  "blockers": []
}
```
`ready_for_real_lookup` = `template_found && tenant_connection_found && status==='connected' && secret_ref_present && base_url_configured`. `blockers` pode conter: `infocap_template_not_found`, `tenant_connection_not_found`, `connection_not_connected`, `missing_credentials`, `missing_base_url`.

## 4. Segurança (não expõe segredo)
A função lê apenas `status`, `connection_config.base_url` (presença) e a **existência** de `encrypted_secret_ref` (booleano `secret_ref_present`). **Nunca** retorna `encrypted_secret_ref`, login, senha, token, headers, CPF ou payload. Logs só com booleans/status/`company_id`. Isolado por `company_id` (uma corretora não vê a conexão da outra).

## 5. Como testar (console do navegador, logado na corretora)
```js
const res = await fetch('/api/attendance/connectors/infocap/diagnostics');
console.log(res.status, await res.json());
```
**Resultados esperados:**
- Resulta/RAFAEL SEGUROS **sem** conexão cadastrada → `template_found:true`, `tenant_connection_found:false`, `ready_for_real_lookup:false`, `blockers:["tenant_connection_not_found"]`.
- Conexão criada mas `draft` / sem secret / sem base_url → `ready_for_real_lookup:false` com o blocker correspondente.
- Conexão `connected` + secret + base_url → `ready_for_real_lookup:true`, `blockers:[]`.

## 6. Próximo passo se faltar conexão
Cadastrar a conexão InfoCap da corretora no Vault `tenant_connections` (template `infocap`), com `connection_config.base_url` (ex.: `https://api.corpnuvem.com`) e a credencial referenciada em `encrypted_secret_ref` — **as credenciais piloto (login/senha) ficam no Vault por corretora, nunca em código/env/RAG/log**. Pode ser feito pela UI/rota de `/api/vault/connections` (cadastro sem segredo) + fluxo de secret do Vault. Depois, `ready_for_real_lookup` vira `true` e o **42I2.1** implementa a chamada HTTP real.
