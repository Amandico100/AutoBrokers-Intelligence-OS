# 42I2.0C — InfoCap Secret Storage Backend Report

> **Status:** concluído · `py_compile` verde · typecheck verde · build verde · `git diff --check` limpo · **backend Python (1 endpoint) + Web proxy (1 rota)** (sem chamada real InfoCap, sem SQL/migration, sem segredo no Web/log/código/RAG/prompt) · sem deploy automático.
> **Data:** 2026-06-15 · **Modelo:** Claude Opus 4.8 · **Branch:** main

## 1. Resumo
Implementado o **fluxo seguro de segredo InfoCap** que faltava (bloqueio do 42I2.0B), espelhando o WhatsApp (39A4.2): o Next recebe login/senha **só server-side**, delega ao **backend** que **cifra (Fernet/EncryptionService)** e grava o ciphertext em `tenant_connections.encrypted_secret_ref`; nada de segredo no Web/log/código. **Sem migration** — a coluna `encrypted_secret_ref` já existe (39A1).

## 2. Auditoria
- `backend/app/services/encryption_service.py`: `get_encryption_service().encrypt/decrypt` (Fernet, chave em `ENCRYPTION_KEY`). **Reutilizado.**
- `backend/app/api/whatsapp_integrations.py`: padrão `_require_internal_key` (header `X-AutoBrokers-Internal-Key` = `BACKEND_INTERNAL_API_KEY`||`ADMIN_API_KEY`, `hmac.compare_digest`) + `get_async_db`. **Espelhado.**
- WhatsApp guarda o segredo em `integrations` (provider-específico, atado a agente). Para InfoCap, **não há tabela genérica de segredo**; a coluna `tenant_connections.encrypted_secret_ref` (39A1) é o storage natural → guardamos **o ciphertext** ali (não é texto puro; ADR-002 ok). **Decisão registrada:** sem migration.

## 4. Backend endpoint (criado)
`POST /attendance/connectors/infocap/secret` — exige chave interna; body `{ company_id, tenant_connection_id, base_url?, username, password }`. Valida: conexão pertence à empresa; template é `infocap`; username/password presentes. **Cifra** `{username,password}` (Fernet) → grava `encrypted_secret_ref`, faz merge de `connection_config.base_url`, define `status='connected'` (se base_url ok) ou `configuring`. Retorna **só flags** (`status`, `base_url_configured`, `secret_ref_present`, `ready_for_real_lookup`). Log só ids/flags — **nunca** login/senha/ciphertext.

## 5. Web proxy (criado)
`POST /api/attendance/connectors/infocap/secret` — Iron Session; recebe `{ username, password, base_url? }`; resolve a `tenant_connection` InfoCap da corretora; encaminha ao backend com a chave interna; **nunca grava o segredo no Web, nunca loga, nunca retorna**. Devolve `diagnostics` sanitizado. (Diferente do 42I2.0B: aqui o segredo é recebido para **encaminhar**, não para armazenar no Web.)

## 6. Precisou SQL/migration? **Não**
Reutiliza `tenant_connections.encrypted_secret_ref` (existente). Nenhuma tabela/coluna nova.

## 7. ready_for_real_lookup fica true?
**Sim**, após gravar o segredo **com base_url**: `status=connected`, `base_url_configured=true`, `secret_ref_present=true` → `ready_for_real_lookup=true`, `blockers=[]`. (Se gravar segredo sem base_url → `configuring`; rode o setup/`base_url` antes ou inclua `base_url` no mesmo POST.)

## 8. Como testar
**Pré-req:** backend deployado com `ENCRYPTION_KEY` e `BACKEND_INTERNAL_API_KEY`/`ADMIN_API_KEY`; conexão InfoCap criada no Vault (draft/configuring).
```js
// grava credenciais piloto da corretora (login/senha são da própria corretora)
await (await fetch('/api/attendance/connectors/infocap/secret', {
  method:'POST', headers:{'Content-Type':'application/json'},
  body: JSON.stringify({ base_url:'https://api.corpnuvem.com', username:'<login da corretora>', password:'<senha da corretora>' })
})).json();
// confirmar
await (await fetch('/api/attendance/connectors/infocap/diagnostics')).json();
// → status:"connected", base_url_configured:true, secret_ref_present:true, ready_for_real_lookup:true, blockers:[]
```
> As credenciais piloto (Resulta/AutoFleet) são **por corretora** e entram por este fluxo seguro — **nunca** no código/repo. Não foram commitadas.

## 9. Segurança
Segredo cifrado com Fernet (chave só no backend via `ENCRYPTION_KEY`); ciphertext só em `encrypted_secret_ref`; **nunca** retornado/logado/no Web/em diagnostics; auth interna Next↔Backend (hmac); isolado por `company_id`.
