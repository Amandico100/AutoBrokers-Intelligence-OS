## 1. Referência do ResultVision antigo (usada como guia, não copiada)
Auditei `server/lib/policyDataProvider/corpInfocapPolicyDataProvider.ts` do ResultVision (branch `clean/agent-runtime-foundation-orphan`). Trechos usados como **referência** (reimplementados no conector novo, sem copiar arquitetura):
- **login** `POST /login {email,senha,aplicacao}` → `token`, `codfil`, `codigo`.
- **cliente por CPF** `GET /cliente_cpf?codfil&cpf_cnpj` → `cliente[0]`.
- **histórico de documentos** `GET /cliente_ligacoes?codigo=<codigo>` → extração aninhada `documentos → documentos/documento`.
- **busca de documentos por texto** `GET /documentos?codfil&texto` (fallback).
- **detalhe da apólice** `GET /documento?codfil&nosnum` → `documento[0]`, `itens`/`coberturas`, `parcelas`.
- **status** `resolveInfocapPolicyStatus`: `cancelado` truthy (`t/true/s/sim/1`) → cancelado; senão `sit_acompanhamento_txt`/`sit_renovacao_txt`/`tipdoc_txt`.

## 2. Fluxo implementado (read-only, encadeado)
`/cliente_cpf` (cliente) → **`/cliente_ligacoes?codigo`** (documentos do cliente) → fallback **`/documentos?codfil&texto=<nome>`** se vazio → **`/documento?codfil&nosnum`** (detalhe, **até 3** docs, falhas parciais toleradas, timeout 8s/req) → normaliza apólices → seleciona.

## 3. Endpoints InfoCap definitivos
`/login`, `/cliente_cpf?codfil=1&cpf_cnpj=<digits>` (CPF), `/lista_clientes?texto=` (nome), `/cliente_ligacoes?codigo=`, `/documentos?codfil&texto=`, `/documento?codfil&nosnum=`. Todos **configuráveis** por `connection_config` (`infocap_ligacoes_path`, `infocap_documentos_path`, `infocap_documento_path`, `infocap_cpf_search_path`, `infocap_codfil`, …) sem mexer no banco.

## 4. Normalização de apólice (sanitizada)
`_sanitize_policy`: `policy_ref` (nosnum/codigo), `masked_policy_number` (numapo/apolice mascarado), `insurer_key` (seguradora_abrev/cia), `product` (ramo_abrev/ramo), `policy_status` (cancelado/sit_*), `valid_from`/`valid_to` (inivig/fimvig), `coverages_count` (itens/coberturas), `cancelled`. **Nunca** CPF/nome/email/telefone crus.

## 5. Seleção segura (estados)
- **0 documentos** → `client_found` (`verification_status` unverified, sem coverage, macro continua `policy_lookup_required`, next_step de validação manual).
- **1 apólice ativa** → `found` → `verification_status='verified_by_connector'`, `policy_source='connector'`, `macro_state='policy_evidence_ready'`, `coverage_evidence` = *"Apólice localizada na InfoCap; cobertura específica ainda depende da leitura dos detalhes/itens."* (`confidence='high'` se itens/ramo mencionam assistência/residencial/elétric; senão `medium`).
- **>1 apólice** → `multiple_matches` (até 5 mascaradas, `requires_human=true`, não escolhe sozinho).
- nome com vários clientes → `multiple_matches` (nível cliente).
- **Cobertura específica NUNCA é afirmada** sem documento/apólice; coberturas detalhadas (itens) ficam para o 42I3 / leitura do PDF.

## 6. Integração policy-lookup
`source:'infocap'` retorna `PolicyLookupResult` compatível: `found` → persiste verified; `client_found`/`policy_lookup_pending` → next_step seguro + metadata; `multiple_matches`; `not_found`; `auth_error`; `provider_error`. **mock/manual inalterados.** `metadata.policy_lookup` persiste `provider`, `matched_by`, `client_found`, `documents_count`, `client_ref` (sanitizado), `requires_human` — sem PII.

## 7. Segurança / logs
Backend loga só `company`, `connection`, `endpoint` (mascarado), `status`, `result_count`, `duration_ms`. Sem CPF/nome/email/telefone/token/segredo/payload. Respostas/diagnostics sem PII crua (refs `codfil`/`codigo`, números mascarados). Timeout 8s/req no backend, 30s no adapter Web (a cadeia faz até ~6 chamadas sequenciais).

## 8. Probe complementar
Não foi necessário um endpoint novo: o `/attendance/connectors/infocap/probe` (42I2.1B) já cobre o diagnóstico; a cadeia de discovery foi implementada direto no `lookup` (com os shapes confirmados pela referência ResultVision + Postman).

```js
console.log(JSON.stringify((await r.json()).policy_lookup_result, null, 2)); // sem CPF

console.log(det.case.verification_status, det.case.policy_source, det.case.metadata?.attendance_macro_state, det.case.next_step);
```

- CPF com **várias** → `multiple_matches` (matches mascarados, `requires_human`).
- CPF **sem documentos** → `client_found` (sem cobertura, next_step de validação).
- **mock** continua funcionando; **not_found** não confirma cobertura.
